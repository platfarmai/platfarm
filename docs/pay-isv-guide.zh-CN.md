# 服务商入驻与运营指南

面向**支付服务商（ISV）、业务操作员、进件审核员与平台管理员**的操作手册：怎么把服务商证书配进系统、怎么帮下级商户进件开户、怎么开通应用与支付通道、怎么管理代理商分润，以及怎么看分账、提现和每日渠道对账。

服务商侧能力全部在**支付中心工作台**（`/api/pay/console/`）与**开放平台控制台**（`/api/openapi/console/`）界面内完成，不提供服务商侧开放 API。下游商户开发团队对接下单、退款与查账接口时，请将另一份文档发给对方：[商户支付开放 API 接入指南](/docs)。

## 1. 角色分工与开通主线

### 1.1 后台角色

登录账号由平台管理员统一创建。不同角色在平台里各司其职：

| 角色 | 使用的后台 | 主要职责 |
|---|---|---|
| 业务操作员 | 支付中心工作台 `/api/pay/console/` | 登记服务商与商户、填写并提交进件草稿、配置应用与支付通道、管理代理商、查看订单与账单 |
| 进件审核员 | 支付中心工作台 `/api/pay/console/` | 复核另一位操作员提交的商户进件单，审核通过后系统才把资料加密报送微信（提交人与审核人不能是同一账号） |
| 平台管理员 | 开放平台 `/api/openapi/console/`、平台控制台 `/platform/console/` | 分配后台登录账号、为下游系统签发 `appKey` / `appSecret` 与 `pay.*` 接口权限、开启每日自动对账任务 |

### 1.2 从零到帮第一个商户收款的 6 步顺序

首次启用支付中心时，按以下顺序操作一遍即可跑通全链路：

1. **登记服务商**（只做一次）：在「商户」页点「新建服务商」，登记你已有的微信支付服务商 / 支付宝 ISV 内部编号与返佣费率。
2. **填服务商渠道参数**（只做一次）：在「应用·通道」页选定该服务商，填入服务商商户号、AppID、API 证书私钥、APIv3 密钥与微信支付公钥（或同步平台证书）。
3. **建立商户档案**：每接入一家商家，先在「商户」页点「新建商户」，挂在你的服务商名下。
4. **提交商户进件并签约**：在「进件审核」页填写商家营业执照、法人、结算银行卡与经营场景，经双人复核提交微信审核；法人扫码完成验证与签约后，系统自动把微信分配的**特约商户号**（`sub_mchid`）写回该商户。（存量已开户商户可跳过进件，直接在「应用·通道」手动填特约商户号。）
5. **创建应用、配支付通道与开放平台权限**：在「应用·通道」页为商户新建应用（保存好只显示一次的签名密钥），按需添加 `WX_JSAPI`、`WX_NATIVE` 等支付通道及手续费率；再由管理员在「开放平台」发放 `appKey` / `appSecret` 并勾选 `pay.*` 权限。
6. **交付凭据给商户上线**：把两套凭据和《商户支付开放 API 接入指南》（`/docs`）交给商户技术团队，先走沙箱或小额实付验证下单、回调与查账，即可正式收款。

## 2. 登记服务商与配置渠道参数

### 2.1 新建服务商

进入「商户」页点「新建服务商」。这里不是向微信新申请服务商资质，而是把你已经在微信支付服务商平台（`pay.weixin.qq.com`）或支付宝开放平台开通好的服务商身份登记到本系统，后续下级特约商户都挂在它名下共用一套证书调用上游接口。

- **服务商号（`isvNo`）与名称**：平台内部台账标识，一般只需建一个服务商。
- **返佣费率（万分位）**：渠道按商户成交额返给服务商的比例（如 `20` = 0.20%），后续给代理商算分润时以此为上限参考。

### 2.2 微信支付服务商参数

进入「应用·通道 → 渠道参数」，下拉选择「给服务商配置」和对应渠道（普通直清选 `wxpay_partner`，电商收付通归集模式选 `wxpay_ecommerce`）：

| 字段 | 必填 | 获取位置与注意事项 |
|---|---|---|
| 服务商商户号 `sp_mchid` | 是 | 10 位数字。微信服务商平台 → 账户中心 → 商户信息。注意填你自己的服务商号，不是下级特约商户号 |
| 服务商 AppID `sp_appid` | 是 | `wx` 开头 18 位，必须是与该服务商关联且主体一致的**已认证服务号、小程序或移动应用**（开放平台「网站应用」AppID 不能用于服务商支付）。在 服务商平台 → 产品中心 → AppID 账号管理 查看或发起关联 |
| 商户 API 证书序列号 `mch_serial_no` | 是 | 40 位十六进制。账户中心 → API 安全 → 商户 API 证书 → 管理证书，必须与下方私钥来自同一张证书 |
| 商户 API 私钥 `private_key` | 是 | 申请证书时生成的 `apiclient_key.pem` 全文（含 `-----BEGIN PRIVATE KEY-----` 首尾行）。保存后加密存储不再回显，后续改其他项时留空即保留原私钥 |
| APIv3 密钥 `api_v3_key` | 是 | 32 位字符，在 API 安全 → 设置 APIv3 密钥 中自行设置，用于解密支付回调与平台证书；填错会导致收不到支付结果通知 |
| 微信支付公钥 ID `wx_public_key_id` + 微信支付公钥 `wx_public_key` | 公钥模式必填 | 近年新开的微信商户号大多为**公钥模式**（API 安全页有「微信支付公钥」一栏）：填入 `PUB_KEY_ID_...` 与下载的 `pub_key.pem` 全文即可，**不需要**点「同步平台证书」 |
| 平台证书序列号 + 平台证书公钥 | 老商户证书模式 | API 安全页没有「微信支付公钥」的老服务商号：先保存上面五项必填，再点页面上的「同步平台证书」按钮自动拉取写入 |

### 2.3 支付宝直付通参数

若开展支付宝直付通（`alipay_zft`）业务，在服务商参数里填写支付宝开放平台应用的 `app_id`、应用私钥 `private_key`、支付宝公钥 `alipay_public_key`（公钥证书模式下额外填写应用公钥证书 SN `app_cert_sn` 与支付宝根证书 SN `alipay_root_cert_sn`）。

## 3. 商户建档与进件开户

### 3.1 进件前向商家收集的资料清单

在动手填表前，先让商家把以下材料准备齐，避免中途反复补件：

- **营业执照**：彩色原件照片或清晰扫描件（企业、个体工商户均需提供；注册号、主体名称、经营者/法定代表人姓名必须与执照一字不差）。
- **法定代表人 / 经营者身份证**：人像面与国徽面彩色照片，必须在有效期内（长期有效可勾长期）。
- **结算银行账户**：**企业**必须填对公银行账户（开户名称 = 营业执照主体名称）；**个体工商户**可填对公账户或经营者本人银行借记卡。需确认开户银行、开户省市及准确支行名称（非 18 家直连大行需精确到支行联行号）。
- **超级管理员（联系人）**：负责接收微信审核通知并扫码签约的人，需提供姓名、手机号、常用邮箱；若超级管理员不是法人本人，还需提供经办人身份证正反面照片、证件有效期及业务办理授权函。
- **经营场景材料**：线下实体店准备**门头照**（含招牌）与**店内环境照**；线上经营准备公众号 / 小程序 AppID 或备案网站域名，并根据实际主营业务选择微信结算行业类目。

### 3.2 新建商户与双人复核提审

1. **先建商户档案**：「商户」页点「新建商户」，选择归属服务商并填写内部展示名称（「商户」页的名称、联系人仅作本系统内部台账，不发给微信）。
2. **填写进件草稿**：「进件审核」页点「新建进件」，选择刚建好的商户，上传证照图片（系统自动走微信图片上传接口加密送达）并填写主体、法人、结算卡、经营场景信息。随时可点「保存草稿」。
3. **敏感信息保护与免重填**：身份证号、银行账号、经办人证件号在数据库内均加密存储，界面只显示脱敏掩码。**编辑已有进件单或被驳回重提时，这三项留空表示保持原值不变**，只有确实填错需要更换时才重新输入完整号码。
4. **双人复核报送渠道**：填表人确认无误后点「提交审核」；由**另一位拥有审核权限的账号**登录进入「进件审核」核对资料，点击「通过并提交渠道」，系统此时才将敏感字段用微信公钥加密并正式调用微信特约商户进件接口。

### 3.3 跟踪审核、签约与子商户号回写

提交微信后，在「进件审核」列表点「同步状态」可随时拉取微信最新进度（常见耗时 1–2 个工作日）：

- **审核驳回（`rejected`）**：列表中会直接展示微信返回的逐字段驳回原因，点击编辑修正对应字段或重传清晰照片（未改动的证件号/银行卡号留空即可），再次走提审复核重提。
- **待账户验证 / 待签约（`need_verify` / `need_sign`）**：按页面提示引导商家完成汇款验证或法人微信扫码确认，最后由超级管理员用微信扫页面展示的签约二维码完成签约。
- **已完成（`finished`）**：微信正式下发 10 位特约商户号（`sub_mchid`），系统**自动将其写入该商户的微信渠道参数**，在「商户」页和「应用·通道」页的「渠道子商户号」列可直接看到。

如果商家早年已经在你的服务商名下开通好特约商户号（或支付宝二级商户 `smid`），无需再走一遍进件：直接在「应用·通道 → 渠道参数」选择「给商户配置」，把已有的 `sub_mchid`（及可选的自有公众号/小程序 `sub_appid`）填进去保存即可。

## 4. 应用、支付通道与凭据发放

### 4.1 创建商户应用与配置支付通道

商户拿到渠道子商户号后，进入「应用·通道」页下半部分「应用与支付通道」：

1. 点「新建应用」，选择所属商户并起名（如「线上商城小程序」「门店收银系统」）。创建成功后弹窗会展示一次 **应用签名密钥**，请立即复制妥善交给商户研发——关闭后平台不再显示明文（遗失只能点「换密钥」轮换，轮换后旧密钥立即失效）。
2. 在该应用行点「配通道」，为商户需要用到的每一种支付方式（如 `WX_JSAPI`、`WX_NATIVE`、`ALI_QR`）绑定对应渠道（如 `wxpay_partner`）并设置**通道手续费率**（平台记账与商户查账按此费率计算手续费）。
3. 后续调整费率或切换通道时，可在通道表格中直接点「编辑」「停用」或「启用」，实时生效。

### 4.2 签发开放平台凭据（`appKey` 与 `scope`）

商户调接口除了上面拿到的 `App-Id` + 签名密钥外，还需要过网关第一层鉴权。请平台管理员打开「开放平台控制台」（`/api/openapi/console/`）：

1. 为该接入方新建调用应用，记录生成的 `appKey` 与 `appSecret`。
2. 按商户实际业务最小化勾选接口权限（scope）：
   - 基础收款与关单：`pay.order.create`、`pay.order.query`
   - 退款与退款查询：`pay.refund.create`、`pay.refund.query`
   - 交易流水与每日账单查询：`pay.bill.query`
   - 订单分账（开通分账的商户）：`pay.division.create`、`pay.division.query`
   - 归集结算与余额提现（仅收付通 / 直付通商户）：`pay.settle.confirm`、`pay.withdrawal.create`、`pay.withdrawal.query`
3. 若商户研发需要先无真钱联调且服务端已开启沙箱（`PAY_SANDBOX=on`），可为其额外建一个测试应用并将通道指向 `sandbox`，切勿把生产应用的通道指向沙箱。

## 5. 代理商与分润管理

如果你通过外部渠道商或业务团队拓展商户，可在「代理商·分润」页记分润账：

- **多级差额分润**：支持最多 **3 级**代理商树，费率单位均为**万分位**（`10` = 0.10%，`30` = 0.30%）。上级代理商给下级设的费率不能高于自己，每级实际拿到的分润是「自身费率 − 直接下级费率」的差额。
- **自动记账与退款冲回**：在页面底部「商户归属」把商户绑定到末端代理商名下后，该商户每成功收款一笔，系统自动按链路给各级代理商记分润；发生退款时按退款比例自动扣回分润。
- **线下结算登记**：本系统**只负责核算与记录分润台账，不会自动向代理商银行卡打款**。你在线下按周期给代理商转账结算后，回到本页点「登记结算」核销已结金额即可。

## 6. 分账、归集提现与每日对账

### 6.1 分账接收方绑定（「分账·台账」页）

需要把单笔订单款项分给供应商、平台或合作方的商户：

1. 先由商户自己登录微信商户平台开通「分账」产品，并授权你的服务商分账权限与最大分账比例。
2. 操作员在「分账·台账」页选中该商户，将其分账接收方（商户号或个人 openid、全称、关系类型、默认分账比例）绑定到渠道。
3. 之后商户业务系统在下单时带分账标识、支付成功后调 `/api/pay/v1/divisions` 发起分账，你在本页可随时查看每张分账单与平台资金台账。

### 6.2 归集余额与提现查看（「提现·余额」页）

- **微信普通服务商（`wxpay_partner`，直清模式）**：买家付款直接进特约商户自己的微信账户，由微信按 T+1 等结算周期自动打款到商户结算银行卡，**不经过平台余额，也不需要提现**——该商户在「提现·余额」页为空属于正常现象。
- **微信收付通（`wxpay_ecommerce`）/ 支付宝直付通（`alipay_zft`）**：属于归集待结算模式，订单经确认结算后进入可提现余额，由商户系统调开放 API 发起提现，操作员在本页核对余额并同步提现到账状态。

### 6.3 每日渠道对账（「对账」页）

对账用于把微信 / 支付宝官方生成的**服务商级交易账单**下载下来，与本系统内同一天成功的支付单、退款单逐笔核对，排查漏单（渠道有本地无）、多单（本地有渠道无）或金额不一致：

- **出单时间**：微信和支付宝当天的官方账单通常在**次日上午 9:00–10:00 之后**才生成完毕，不要对今天，也不要在早上 9 点前手动对昨天。
- **一键开启每日自动对账**：由平台管理员在「对账」页点击一次「注册每日自动对账」，系统此后每天下午会自动把所有已配妥渠道参数的服务商昨日账单拉取核对一遍。运营人员日常只需定期打开「对账」页确认批次状态为完成且「差异」笔数为 `0`；若出现差异，点开明细即可定位具体单号处理补单或差错。
