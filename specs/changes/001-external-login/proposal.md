# 001: Third-party Login (svc-oauth + external-login exchange)

[English](proposal.md) | [简体中文](proposal.zh-CN.md)

## Motivation

The platform currently only supports username/password login. We need GitHub / WeChat / etc. without violating the "auth base never grows fat" rule (no third-party SDKs inside auth).

## Design

Final design: [architecture-v2.md Appendix G](../../../docs/architecture-v2.md). Key points:

- One-time auth changes: `external_identities` table + `POST /internal/auth/external-login` (internal network + service-token whitelist only) + `POST /auth/bind-external`
- svc-oauth owns the full OAuth dance (authorize/callback/state/PKCE), one module per provider
- Frontend delivery uses a 30-second one-time exchange code — JWTs must never appear in redirect URLs

### Contract changes

- auth adds the two endpoints above; claims shape is **unchanged**
- svc-oauth `service.yaml`: `mount.path: /api/oauth`, authorize/callback as `public_routes`
- First real use of auth `accept_service_tokens` (whitelist svc-oauth)

## Blast radius

- `platform/auth`: +1 table, +2 endpoints (~150 lines)
- New service `services/svc-oauth`
- Gateway config: auto-generated by `pctl sync`, no hand edits
- Existing services: zero impact

## Acceptance

```bash
# GitHub flow (manual): /api/oauth/github/authorize → authorize → landing page gets one-time code → exchange for token pair
# Automated:
pctl check --e2e                          # no regression on existing contracts
curl -X POST .../internal/auth/external-login  # 404 outside gateway; 401 without service token on internal net
# Same externalId on a second login returns the same userId (idempotent)
```
