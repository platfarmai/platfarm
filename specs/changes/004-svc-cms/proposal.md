# 004: svc-cms — Content Management Service (membership + editorial roles)

[English](proposal.md) | [简体中文](proposal.zh-CN.md)

## Motivation

Build a CMS on PlatFarm as the first real business service that exercises the permission-manifest vocabulary (specs/003). Editorial roles (`admin`/`editor`/`author`) live in the service, not in platform auth — L3 resource permission stays with the content owner.

## Design

### Scope (this delivery = backend MVP)

- First-party Go service `svc-cms` (gin template)
- Tables: `cms_members` (user_id, role) + `contents` (title/body/status/owner_id)
- Role matrix + content state machine (`draft → in_review → published → archived`)
- Public read of published content; authenticated CRUD gated by role
- Contract tests: 401 / 200 / **author cannot publish → 403**

### Role matrix

| Action | admin | editor | author |
|---|---|---|---|
| Manage members | ✅ | ❌ | ❌ |
| Edit/publish any content | ✅ | ✅ | ❌ |
| Create / edit own draft / submit for review | ✅ | ✅ | ✅ |

### Manifest (consumes 003)

```yaml
manifest: v1
roles:
  vocabulary:
    - { name: admin,  desc: Manage members and all content }
    - { name: editor, desc: Edit and publish all content }
    - { name: author, desc: Create and edit own drafts }
  bootstrap: platform-admin=admin
exposes:
  scopes:
    - { name: read, desc: Read published content }
```

### Deferred (not this delivery)

- Shared svc-grants (trigger: second membership-bearing service) — CMS uses a local `cms_members` table behind a thin accessor so a later swap is zero-touch
- Admin SPA (management UI) — API-first; UI is a follow-up
- Media library (svc-file + MinIO)

## Blast radius

New `services/svc-cms` only. Platform contracts unchanged (uses 003 fields). Gateway regenerated by `pctl sync`.

## Acceptance

```bash
pctl check --e2e                              # all services including svc-cms green
# Author token cannot publish → 403
# Editor/admin can publish → 200
# Public GET /api/cms/public/contents returns published only
# Platform admin first call auto-bootstraps as cms admin
```
